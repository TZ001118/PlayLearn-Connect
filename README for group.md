# 组员更新日志

这份文件用于整理 PlayLearn 最近完成的主要更新。内容按照学生端、家长端和管理端分开记录，方便后续分工、检查和演示。

## 学生端

1. 更新了注册逻辑。
   - 公开注册页现在主要用于家长注册。
   - 儿童账号改为由家长在家长端创建。
   - 这样可以避免年龄较小的儿童自行创建账号，也让账号归属关系更清楚。

2. 更新了生日限制。
   - 儿童账号年龄限制为 4 到 12 岁。
   - 注册和创建儿童账号时，不应再出现未来年份或明显不合理的生日。

3. 更新了生日修改规则。
   - 儿童生日创建后不能随意修改。
   - 这样可以避免用户通过修改生日影响年龄分层、推荐和统计结果。

4. 更新了儿童 IC / ID 信息。
   - 家长创建儿童账号时可以填写 IC / ID。
   - 管理端也可以查看相关信息，方便账号核对。

5. 更新了学生资料页。
   - 学生可以看到自己的基本资料。
   - 学生可以看到最近游戏记录。
   - 学生可以看到家长设置的重点练习目标。

6. 更新了头像框功能。
   - 新增了头像框资源。
   - 学生可以在资料页选择头像框。
   - 头像框会显示在学生资料、排行榜和家长端相关位置。

7. 更新了游戏记录。
   - 学生玩游戏后的记录会被保存。
   - 记录包含分数、等级、时间和部分学习表现数据。

8. 更新了游戏教程。
   - Memory 增加了 How to Play 教程。
   - 2048 增加了 Help 教程入口。
   - 这样演示时可以说明游戏有基础玩法说明。

9. 更新了游戏封面。
   - 多个默认游戏的封面已经调整为更统一的视觉风格。
   - 首页游戏卡片看起来比之前更一致。

10. 更新了游戏反馈流程。
   - 学生可以对游戏提交评论。
   - 评论内容可以在管理端统一查看。

## 家长端

1. 更新了命名方式。
   - 家长端尽量使用 Children，而不是 Student。
   - 因为家长端管理的是自己的孩子，这样表达更准确。

2. 更新了儿童账号创建流程。
   - 家长可以在家长端创建儿童账号。
   - 创建时需要填写用户名、密码、性别、生日和 IC / ID。
   - 创建后会自动和家长账号绑定。

3. 更新了账号绑定逻辑。
   - 现在主要由家长账号去创建和绑定儿童账号。
   - 不再鼓励儿童账号主动绑定家长账号。
   - 这样账号关系更安全，也更符合家长控制逻辑。

4. 更新了学习能力雷达图。
   - 雷达图对应六项能力：Math、Logic、Memory、Focus、Speed、Creativity。
   - 这些能力不再只是固定展示，而是可以根据游戏记录和游戏能力权重进行计算。

5. 更新了游戏能力权重。
   - 每个游戏可以对应多个能力。
   - 例如一个游戏可以是 Logic 40%、Memory 20%、Focus 20%、Math 10%、Speed 10%。
   - 这样家长端看到的能力分析会更接近真实学习表现。

6. 更新了学习目标功能。
   - 家长可以给孩子设置重点练习方向。
   - 例如希望孩子更专注 Memory，或提高 Logic。
   - 学生端可以看到家长希望自己关注什么能力。

7. 更新了学习数据分析。
   - 数据不再只看分数。
   - 现在也开始记录正确率、反应时间、游戏次数、持续时间和历史记录。
   - 这些数据会用于后续学习表现分析。

8. 更新了历史记录页面。
   - 家长可以查看孩子之前的游戏记录。
   - 这样可以更清楚地看到孩子过去玩过什么、表现如何。

## 管理端

1. 更新了用户管理页面。
   - 管理员可以查看玩家和家长的详细资料。
   - 管理员可以查看账号状态、生日、IC / ID、加入时间和封禁信息。

2. 更新了亲子账号关系显示。
   - 管理员可以看到儿童账号绑定了哪个家长。
   - 管理员也可以看到家长账号下面绑定了哪些儿童。

3. 更新了封禁账号功能。
   - 管理员封禁账号时必须填写原因。
   - 用户详情中可以看到封禁原因和封禁时间。

4. 更新了游戏管理功能。
   - 管理员可以设置游戏分类。
   - 管理员可以设置游戏适合年龄。
   - 管理员可以设置六项学习能力权重。

5. 更新了游戏包上传功能。
   - 管理员可以上传标准游戏包。
   - 游戏包需要包含 `manifest.json` 和 `index.html`。
   - 游戏包可以使用 zip 上传，也可以上传解压后的文件夹。
   - 如果服务器不支持 zip 解压，也可以使用文件夹上传方式。

6. 更新了游戏包安全限制。
   - 上传游戏包不允许包含 PHP 文件。
   - 游戏包主要支持 HTML、CSS、JavaScript、JSON、图片和音频资源。
   - 这样可以减少服务器端安全风险。

7. 更新了游戏开发接入方式。
   - 新增了 PlayLearnGame SDK。
   - 游戏开发者只需要调用 SDK 提交分数和学习数据。
   - 游戏不需要直接处理数据库，也不需要了解 `save_score.php` 的内部细节。

8. 更新了开发模板。
   - 新增了 `developer_game_template`。
   - 模板中包含游戏包需要的基本文件。
   - 之后新增游戏时，可以按照模板结构制作。

9. 更新了玩家分数记录页面。
   - 管理员可以查看所有游戏记录。
   - 记录中包含玩家、游戏、等级、分数、正确率、反应时间和游玩时间。
   - 管理员可以点击 Inspect 查看更详细的数据。

10. 更新了评论管理页面。
   - 管理员可以查看学生和家长提交的评论。
   - 管理员可以查看评论数量、平均评分和异常类型数据。
   - 管理员可以删除不合适评论。

11. 更新了用户详情弹窗。
   - 管理员点击 View 后，可以看到该用户的近期游戏记录。
   - 管理员也可以看到该用户的近期评论。
   - 游戏记录和评论都可以跳转到对应管理页面。

12. 更新了危险操作提示。
   - 删除评论、删除游戏、清空记录和维护模式操作都改成了系统内弹窗。
   - 不再使用浏览器原生确认框。
   - 弹窗视觉风格更接近管理端现有设计。

13. 更新了维护模式操作。
   - 管理员可以在设置页开启或关闭维护模式。
   - 开启时可以填写预计维护时间。
   - 关闭时会出现系统内确认弹窗。

14. 更新了后台 UI 一致性。
   - 管理端多个弹窗和按钮风格进行了统一。
   - 学生端、家长端和管理端之间的整体风格比之前更接近。

15. 更新了代码可维护性。
   - 清理了不应该出现在正式代码中的控制台输出。
   - 将部分简写 JavaScript 和 CSS 改成更容易阅读的写法。
   - 文档也重新整理为更清楚的说明结构。

## 目前项目代码量

1. 不包含第三方库、上传资源、生成文件和模板文件时，项目自写代码大约为 13,500 行。
2. 统计范围主要包括 PHP、HTML、CSS 和 JavaScript。
3. 第三方邮件库和上传游戏包文件不计入这个数字。
